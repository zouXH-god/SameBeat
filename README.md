# 同频 · 绝对同步音乐室

**让多台设备跟着同一条时间轴播放，每个人都能调出自己的伴奏与人声比例。**

同频是一个基于浏览器的多人音乐室。房主上传伴奏、人声和歌词，分享链接或六位房间编号，其他设备即可加入；房主统一控制播放进度，听众独立调整本机混音。适合一起听歌、个人练唱、小组排练，以及在电脑或手机上展示同步歌词。

无需安装客户端，也没有前端构建步骤：使用 Node.js 20+ 启动服务后，通过浏览器访问即可。

## 一眼了解功能

| 功能 | 可以做什么 |
| --- | --- |
| 多设备同步播放 | 房主统一播放、暂停、停止和跳转；成员中途加入、断线重连后重新对齐 |
| 双音轨混音 | 分别上传伴奏与人声，也支持单音轨；每台设备独立调整音量与混音预设 |
| 成员混音管理 | 房主查看并定向调整在线成员的混音，成员仍可随时自行修改 |
| 同步歌词 | 上传 LRC，跟随房间进度显示；支持房间歌词偏移和本机视觉提前量 |
| 歌词 MV | 两行分组、词语动画、下一组预览、字体与文字样式设置、全屏展示 |
| 自定义 MV 背景 | 纯色、本地图片或视频，支持 RGBA 遮罩及视频正放／倒放往返循环 |
| 本地偏好记忆 | 保存本机混音、歌词显示和 MV 设置；背景媒体保存在当前浏览器 |
| 房间持久化 | 服务重启后保留音轨、歌词与房主身份，以暂停状态恢复房间 |

> “绝对同步”是项目名称。系统通过时钟校准和漂移修正尽量对齐播放，实际扬声器同步误差尚未实测，不承诺跨网络、跨硬件的零误差。本项目播放预先上传的音频，不提供实时麦克风连麦。

## 快速开始

### 1. 安装并启动

环境要求：Node.js 20 或更新版本、npm，以及支持 Web Audio API 和 WebSocket 的现代浏览器。

```powershell
npm install
npm start
```

打开 [本机音乐室](http://localhost:3000)。开发时可运行 `npm run dev` 自动重启服务端，修改前端文件后刷新浏览器。

如果全局 npm 缓存目录没有权限，可使用 `npm install --cache .npm-cache`。

### 2. 创建房间并播放

1. 填写称呼并创建音乐室。
2. 上传伴奏、人声中的一条或两条；需要歌词时，再上传 UTF-8 编码的 LRC 文件。
3. 点击“启用声音”，等待音轨加载与时钟校准就绪，再点击播放。
4. 分享链接或六位房间编号。新设备加入并启用声音后，会从房间当前进度开始播放。
5. 各设备分别调整伴奏、人声与主输出音量；房主负责统一播放进度。

房主凭证保存在创建房间的浏览器 localStorage 中。清除站点数据会失去管理权限，请保留该浏览器的数据。

### 3. 使用合成示例体验

```powershell
npm run demo
```

命令会在 `data/demo/` 中生成两条 30 秒合成音轨和歌词。将它们上传到房间，即可体验播放、混音与歌词跟随；示例旋律不是真实人声。

## 详细使用说明

### 房间与播放控制

- 房主可播放、暂停、继续、停止、跳转，以及调整音轨和歌词的房间偏移。
- 替换音轨会暂停房间，成员加载新版本后才能就绪，暂不支持无缝切换资源。
- 播放默认不等待所有成员就绪，未就绪的成员准备好后再加入当前进度。
- 掉线时，已解码音频继续沿原时间轴播放；重连或页面恢复前台后重新对齐。
- 后台与锁屏播放受浏览器和操作系统限制。

### 音轨上传与独立混音

每条音轨最大 100 MB、最长 4 小时。实际可用音频格式取决于浏览器的解码支持，音频时长由房主浏览器解码后上报。

每台设备独立保存伴奏、人声音量和混音预设，刷新或重新加入后恢复。主输出音量仅由本机调节。房主可在“一起聆听”中查看并调整指定在线成员的混音，只对该成员生效；成员收到提示后仍可自行修改。

### LRC 歌词与时间偏移

支持普通多时间戳 LRC，以及正文中穿插方括号或尖括号逐字时间戳的增强 LRC。行首连续时间戳表示整行重复出现，正文里的逐字时间戳不会生成重复行。增强 LRC 当前按行显示，暂未实现精确逐字高亮。

歌词时间设置分为两层：

| 设置 | 生效范围 | 用途 |
| --- | --- | --- |
| 房间歌词偏移 | 整个房间，由房主调整 | 校正歌词文件与音频的相对时间 |
| 视觉提前 | 当前浏览器，所有成员均可调整 | 提前看到下一句，便于跟唱 |

普通歌词与 MV 默认提前 200 ms 显示。可在歌词面板或 MV 工具栏将“视觉提前”设为 -1000–1000 ms；正数提前、负数延后，设为 0 关闭提前。此设置仅保存在本机，不改变音频时间轴或歌词文件偏移。

```text
歌词显示时间 = 播放进度 - 房间歌词偏移 + 本机视觉提前量
```

### 歌词 MV：展示与动画

在歌词面板点击“歌词 MV”打开动画模式，默认黑底白字。所有成员均可观看，房主可在 MV 内播放／暂停。

- 每次展示两行歌词，第二行唱完切换下一组；最后剩一行时单独展示。
- 下一组最多两行显示在主歌词下方偏右，大小为主歌词的 48%，不透明度为 32%；无后续歌词时隐藏。
- 换组时，旧歌词缩小移向左上并淡出，预览沿原位置放大接替，新预览随后淡入，转场约 600 ms。
- 浏览器使用本地 jieba 分词，为词语设置不同字号与固定的 ±3° 微倾斜；单行长句自动缩小适配。
- 词语淡入、上移和换组均由房间时间轴推导，随暂停和跳转更新。词级动画按文本长度估算，暂非精确逐字卡拉 OK。

新上传的逐字歌词会保留句尾结束时间，以便在间奏前换组；普通 LRC 使用下一行开始时间或音频结束时间推断。旧歌词如需句尾信息，需要重新上传。

点击“全屏”可铺满屏幕，支持情况取决于浏览器；不支持时仍可铺满窗口。按 Esc 退出全屏，再按 Esc 关闭 MV，也可使用关闭按钮。当前 MV 用于实时展示，暂不导出视频文件。

### 歌词 MV：字体与文字样式

| 设置 | 可调内容 |
| --- | --- |
| 字体 | 黑体、微软雅黑、宋体、楷体、仿宋、系统默认；未安装时使用备用字体 |
| 字号与间距 | 最小／最大字号 8–200 px，行间距 0–120 px |
| 文字颜色 | RGBA 颜色与透明度 |
| 阴影 | 开关、RGBA 颜色、模糊半径、水平／垂直偏移 |
| 描边 | 开关、RGBA 颜色与宽度 |
| 位置偏移 | 以歌词可用区域中心为原点，X／Y 各 ±4000 px，可分别归零 |

X 正值向右、Y 正值向下，负值反向。设置即时应用于主歌词与预览，仅保存在当前浏览器，并可一键恢复默认。字号范围用于词语编排，长句或小屏幕仍会整体缩小以适应画面，预览沿用主歌词的缩小比例。

所有颜色统一使用 RGBA 调色板，可直接输入 `rgba()`，RGB 使用系统色盘，透明度为 0–1。旧 HEX 颜色、文字／阴影透明度和背景压暗值会自动迁移。

### 歌词 MV：背景与视频循环

点击工具栏“背景”，可选择纯色、本地图片或本地视频，调整 RGBA 遮罩，或恢复黑色背景。图片与视频居中裁切铺满，视频静音播放。

视频默认普通循环。开启“无限循环”后，按正放 → 倒放 → 正放往返播放：

- 初始化首帧缓存后，从头正放一次，并将最高 720p／30 fps 的压缩画面写入本机临时 IndexedDB 缓存。
- 首次正放保持原画质，之后正放和倒放使用缓存画面，在同一画布上连续绘制。
- 跨端点预读画面并保留时间余量，避免转向时重新启动播放器或重复停留在首尾帧；解码预读窗口约 9 帧。
- 更换视频、关闭往返循环或离开页面时清理临时缓存。缓存失败时提示并回退逐帧定位。
- 关闭 MV 或切到后台时暂停，恢复后继续当前方向；关闭“无限循环”则恢复普通循环。

背景及遮罩偏好存于 localStorage，最近选择的媒体存于本机 IndexedDB，可在刷新后恢复。背景媒体不上传服务器，也不同步给其他设备；可保存的大小与格式受浏览器存储配额和解码能力限制。

## 部署与数据管理

### 配置项与持久化

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 与 WebSocket 服务端口 |
| `DATA_DIR` | 项目下的 `data/` | 房间状态和上传文件目录 |
| 监听地址 | `0.0.0.0` | 默认允许其他设备通过服务器地址访问 |

PowerShell 配置示例：

```powershell
$env:PORT = '8080'
$env:DATA_DIR = 'E:\music-room-data'
npm start
```

房间状态保存在 `data/rooms.json`，上传文件保存在 `data/uploads/`（设置 `DATA_DIR` 后使用对应目录）。备份时应同时保留房间状态和上传文件。服务重启后保留资源与房主身份，播放以暂停状态恢复。

### 局域网与互联网访问

局域网设备应通过服务器的局域网 IP 访问，例如 `http://192.168.1.10:3000`；分享前将链接中的 `localhost` 替换为实际 IP，并确保端口可访问。

异地加入需要部署到可访问的主机，配置 HTTPS 和支持 WebSocket 的反向代理。`localhost` 链接只能访问当前设备。

### 当前边界

当前为单进程原型，尚无账户系统、房间密码、配额清理、多实例协调和生产级限流。上传文件通过随机地址访问，正式公开部署前需要完善访问控制与资源管理。

界面显示的同步数值来自时钟与 AudioContext 的估计，不能证明达到 20–50 ms 的实际发声精度。公网延迟、浏览器调度和设备音频输出均可能影响最终效果。

## 开发与实现

### 目录导航

```text
public/           浏览器界面、音频引擎、歌词 MV 与静态素材
server/           HTTP / WebSocket 服务与房间管理
shared/           服务端和客户端共用的时间轴、歌词与混音逻辑
scripts/          合成示例与主题素材处理脚本
test/             单元测试与 HTTP / WebSocket 集成测试
docs.md           技术设计文档
```

[技术设计文档](./docs.md) 记录整体方案；当前实现使用 Node.js、原生 JavaScript 模块、WebSocket 和 Web Audio API，以源码及本文说明为准。

### 同步机制

- `shared/timeline.js`：以基准位置和服务器开始时间推导播放进度，不广播高频进度计数器。
- `server/index.js`：维护权威房间状态、房主权限、资源版本和成员就绪状态。播放控制预约在未来 700 ms 统一生效，生效前保留原时间轴。
- `public/app.js`：通过 `performance.now()` 和四时间戳校准，选择低 RTT 样本估计服务器时钟；资源版本一致且声音已启用才报告就绪。
- `public/audio.js`：两条 BufferSource 在同一 AudioContext 中共用启动时刻，独立 GainNode 平滑调整本机混音，主输出经过压缩器。
- 每 3 秒估计软件播放漂移；10–200 ms 时同速微调两轨，超过 200 ms 时重新调度；每 15 秒重新采样时钟。
- `revision` 防止旧房间状态覆盖新状态；独立的 `playbackRevision` 避免歌词或成员状态变化重启音源。本机混音直接更新增益，不改变房间版本或播放时间轴。
- 歌词、进度条和 MV 读取同一房间时间轴。`public/mv.js` / `shared/mv.js` 负责分词、编排和动画，相关 JS／WASM 由本服务分发，无需第三方 CDN。

### 界面主题与素材

界面以金橙短发、猫耳、粉色绒领外套的女孩为主形象，配色使用奶油白、灰粉、蜂蜜金与鼠尾草绿。`public/theme.css` 维护主题变量、响应式布局与 MV 控件外观；歌词画布和用户的 MV 配色独立设置。

`public/assets/` 包含六组 ImageGen 绘制素材：`mascot` 主立绘、`forest` 森林长椅、`avatar` 头像、`listening` 聆听封面、`waiting` 歌词空状态、`botanical` 花叶装饰。PNG 为原图，WebP 用于网页，透明素材保留 alpha；`favicon.png` 为站点图标。六张 WebP 合计约 468 KiB，生成提示词保存在 `prompts.json`，不通过静态图片路由公开。

重新导出素材时，先修改 `scripts/prepare-theme-assets.cjs` 中的来源文件名，再运行：

```powershell
node scripts/prepare-theme-assets.cjs <图片目录>
```

该脚本需要本地或 Codex 桌面内置的 `sharp`，正常运行网站不需要此依赖。

### Git 提交范围

仓库保留运行源码、测试、依赖锁定文件、设计文档与界面素材。以下本地内容通过 `.gitignore` 排除：

- `node_modules/`、`.npm-cache/`：依赖与安装缓存。
